# Data Model: Idea Printer

**Feature**: Idea Printer  
**Branch**: `001-idea-printer`  
**Date**: December 23, 2025  
**Status**: Complete  
**Storage**: Client-side localStorage (browser-based, device-specific)

## Overview

This document defines the data entities, relationships, validation rules, and state transitions for the Idea Printer feature. Entities are derived from [spec.md](spec.md) Key Entities section and functional requirements.

**Architecture Decision**: Data is stored in browser localStorage instead of a backend database to minimize hosting costs and simplify deployment. This means:
- Data is device-specific (no cross-device synchronization)
- Data persists until browser cache is cleared
- No server-side persistence or multi-user data access
- API keys are encrypted before localStorage storage

---

## Entity 1: Generated Idea

**Description**: Represents a complete app concept with structured components matching the printer output format. Stored in localStorage as JSON.

### Fields

| Field | Type | Required | Validation | Description |
|-------|------|----------|------------|-------------|
| `id` | UUID | Yes | Valid UUID v4 | Unique identifier for the idea |
| `appName` | String | Yes | 3-50 chars, alphanumeric + spaces | Memorable name for the app concept |
| `category` | String | Yes | 3-30 chars, one of predefined categories | Market segment (e.g., Travel, Finance, Education) |
| `concept` | String | Yes | 10-200 chars | One-sentence description of what the app does |
| `theGap` | String | Yes | 20-500 chars | Clear statement of the market problem being addressed |
| `theFix` | String | Yes | 20-500 chars | Explanation of how the app solves the identified problem |
| `generatedAt` | Timestamp | Yes | ISO 8601 format | When the idea was created |
| `uniqueId` | String | Yes | 8 chars, alphanumeric uppercase | Display ID for the printout (e.g., "NI4QMZ2B") |
| `deletedAt` | Timestamp | No | ISO 8601 format | Soft delete timestamp (null if active) |

### Storage Structure

```typescript
// localStorage key: 'ideaPrinter_generatedIdeas'
// Value: Array of GeneratedIdea objects
interface GeneratedIdea {
  id: string;
  appName: string;
  category: string;
  concept: string;
  theGap: string;
  theFix: string;
  generatedAt: string; // ISO 8601
  uniqueId: string;
  deletedAt?: string;
}
```

### Relationships

- **Linked to**: Generation Request (1..1 relationship via requestId in memory)

### Validation Rules

- `appName` must not contain special characters except spaces and hyphens
- `category` must be one of: Technology, Travel, Finance, Health, Education, Entertainment, Productivity, Social, E-commerce, Other
- `concept` must be a complete sentence (ends with punctuation)
- `theGap` and `theFix` must be distinct (no duplicate content)
- `uniqueId` must be unique across all generated ideas in localStorage (collision check on insert)

### State Transitions

Generated Ideas are immutable once created (no state transitions). They can only be:
1. **Created**: When AI generation completes successfully, saved to localStorage
2. **Deleted**: When user explicitly removes from history (soft delete with `deletedAt` timestamp)

## Entity 2: User Configuration

**Description**: Represents optional user-provided settings including service credentials and generation preferences. Stored in localStorage as a single JSON object.

### Fields

| Field | Type | Required | Validation | Description |
|-------|------|----------|------------|-------------|
| `id` | UUID | Yes | Valid UUID v4 | Unique identifier for the configuration |
| `geminiApiKey` | String | No | Starts with "AIza", 39 chars | Encrypted user-provided Gemini API key |
| `preferredCategories` | String[] | No | Array of valid category names | User's preferred idea categories for filtering |
| `generationCount` | Integer | Yes | Non-negative integer | Total ideas generated by this user |
| `createdAt` | Timestamp | Yes | ISO 8601 format | When configuration was first created |
| `updatedAt` | Timestamp | Yes | ISO 8601 format | Last modification time |

### Storage Structure

```typescript
// localStorage key: 'ideaPrinter_userConfig'
// Value: Single UserConfiguration object
interface UserConfiguration {
  id: string;
  geminiApiKey?: string; // encrypted
  preferredCategories?: string[];
  generationCount: number;
  createdAt: string; // ISO 8601
  updatedAt: string; // ISO 8601
}
```

### Validation Rules

- `geminiApiKey` must be encrypted using Web Crypto API (AES-GCM) before localStorage storage
- `geminiApiKey` format validation before acceptance (Gemini key pattern: starts with "AIza")
- `preferredCategories` array max length: 5 items
- `generationCount` incremented on each successful generation

### State Transitions

1. **Initial**: Created with default settings, no API key
2. **Configured**: User adds custom API key
3. **Active**: Configuration actively used for generation
4. **Cleared**: User removes custom API key (reverts to default)

## Entity 3: Generation Request

**Description**: Represents a single request for idea generation including timestamp, status, and result reference. Stored in sessionStorage for current session only (cleared on browser close).

### Fields

| Field | Type | Required | Validation | Description |
|-------|------|----------|------------|-------------|
| `id` | UUID | Yes | Valid UUID v4 | Unique identifier for the request |
| `status` | Enum | Yes | One of: pending, success, failed | Current request status |
| `startedAt` | Timestamp | Yes | ISO 8601 format | When generation was initiated |
| `completedAt` | Timestamp | No | ISO 8601 format | When generation finished (success or failure) |
| `durationMs` | Integer | No | Non-negative integer | Time taken to generate (milliseconds) |
| `errorMessage` | String | No | 0-500 chars | Error details if status is "failed" |
| `generatedIdeaId` | UUID | No | Valid UUID v4 | Reference to resulting Generated Idea (if success) |
| `apiKeySource` | Enum | Yes | One of: default, user_provided | Which API key was used |

### Storage Structure

```typescript
// sessionStorage key: 'ideaPrinter_currentRequests'
// Value: Array of GenerationRequest objects (cleared on browser close)
interface GenerationRequest {
  id: string;
  status: 'pending' | 'success' | 'failed';
  startedAt: string; // ISO 8601
  completedAt?: string; // ISO 8601
  durationMs?: number;
  errorMessage?: string;
  generatedIdeaId?: string;
  apiKeySource: 'default' | 'user_provided';
}
```

### Relationships

- **Linked to**: Generated Idea (optional, 0..1 relationship - only if success)

### Validation Rules

- `completedAt` must be after `startedAt` (temporal consistency)
- `durationMs` must match `completedAt - startedAt` (calculated field)
- If `status` is "success", `generatedIdeaId` must be set
- If `status` is "failed", `errorMessage` must be set
- `durationMs` should trigger alert if > 5000ms (exceeds performance requirement)

### State Transitions

```
pending → success (idea generated successfully)
pending → failed (API error, timeout, validation failure)
```

No transitions allowed from terminal states (success/failed).

### Storage Helper Functions

```typescript
// localStorage helper utilities (lib/utils/storage.ts)
class IdeaStorage {
  // Generated Ideas
  static getIdeas(): GeneratedIdea[] {
    const data = localStorage.getItem('ideaPrinter_generatedIdeas');
    return data ? JSON.parse(data) : [];
  }
  
  static saveIdea(idea: GeneratedIdea): void {
    const ideas = this.getIdeas();
    ideas.push(idea);
    localStorage.setItem('ideaPrinter_generatedIdeas', JSON.stringify(ideas));
  }
  
  static deleteIdea(ideaId: string): void {
    const ideas = this.getIdeas();
    const updated = ideas.map(idea => 
      idea.id === ideaId ? { ...idea, deletedAt: new Date().toISOString() } : idea
    );
    localStorage.setItem('ideaPrinter_generatedIdeas', JSON.stringify(updated));
  }
  
  // User Configuration
  static getConfig(): UserConfiguration | null {
    const data = localStorage.getItem('ideaPrinter_userConfig');
    return data ? JSON.parse(data) : null;
  }
  
  static saveConfig(config: UserConfiguration): void {
    localStorage.setItem('ideaPrinter_userConfig', JSON.stringify(config));
  }
  
  // Generation Requests (sessionStorage)
  static getRequests(): GenerationRequest[] {
    const data = sessionStorage.getItem('ideaPrinter_currentRequests');
    return data ? JSON.parse(data) : [];
  }
  
  static saveRequest(request: GenerationRequest): void {
    const requests = this.getRequests();
    requests.push(request);
    sessionStorage.setItem('ideaPrinter_currentRequests', JSON.stringify(requests));
  }
}
```

## Performance Considerations

### localStorage Limits

- **Size Limit**: Most browsers allow 5-10 MB per domain
- **Estimated Storage**: Each idea ~1KB, supports ~5,000-10,000 ideas before hitting limits
- **Mitigation**: Implement pagination and allow users to clear old history

### Data Access Performance

- localStorage is synchronous and fast (< 1ms read/write)
- No network latency (data is local)
- No database connection overhead

### Data Retention

- Ideas persist until user clears browser data
- sessionStorage cleared on browser tab close
- Implement "Clear History" and "Export Data" features for user control

## Security Considerations

### API Key Encryption

User-provided Gemini API keys must be encrypted before localStorage storage:

```typescript
// Use Web Crypto API for AES-GCM encryption
async function encryptApiKey(apiKey: string, masterKey: CryptoKey): Promise<string> {
  const encoder = new TextEncoder();
  const data = encoder.encode(apiKey);
  const iv = crypto.getRandomValues(new Uint8Array(12));
  
  const encrypted = await crypto.subtle.encrypt(
    { name: 'AES-GCM', iv },
    masterKey,
    data
  );
  
  // Return base64-encoded IV + ciphertext
  return btoa(String.fromCharCode(...iv) + String.fromCharCode(...new Uint8Array(encrypted)));
}
```

### Master Key Generation

- Generate master key from user session or device fingerprint
- Store in sessionStorage (cleared on browser close)
- Never store master key in localStorage

## Summary

Three core entities stored in browser storage:
1. **Generated Idea**: Immutable app concepts in localStorage (persistent)
2. **User Configuration**: Settings and encrypted API key in localStorage (persistent)
3. **Generation Request**: Session audit trail in sessionStorage (temporary)

All validation rules enforce data integrity and align with functional requirements (FR-001 through FR-012 in spec.md). No backend database required, reducing hosting costs to zero for storage layer.
